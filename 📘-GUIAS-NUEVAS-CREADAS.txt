┌──────────────────────────────────────────────────────────────────────────────┐
│  🔄 WORKFLOW MEJORADO DE UNIDAD                                              │
└──────────────────────────────────────────────────────────────────────────────┘

    ANTES (4 estados):
    available → reserved → sold → (blocked)

    AHORA (13 estados):
    available
      ↓ POST /api/units/{id}/put_on_option/
    option (24-48h)
      ↓ POST /api/units/{id}/separate/
    separated (con señas)
      ↓ POST /api/units/{id}/reserve/
    reserved (formal)
      ↓ (proceso legal)
    contract_pending
      ↓ POST /api/units/{id}/sign_contract/
    contract_signed
      ↓ POST /api/units/{id}/record_payment/ (enganche)
    in_payment
      ↓ POST /api/units/{id}/record_payment/ (última cuota)
    paid
      ↓ (construcción completa)
    ready_for_delivery
      ↓ POST /api/units/{id}/schedule_delivery/
    delivery_scheduled
      ↓ POST /api/units/{id}/deliver/
    delivered

    CADA TRANSICIÓN:
    • Validada
    • Trackeada en operation_history
    • Notificaciones automáticas
    • Actualiza contadores del proyecto


┌──────────────────────────────────────────────────────────────────────────────┐
│  💡 CASOS DE USO DEL MUNDO REAL                                              │
└──────────────────────────────────────────────────────────────────────────────┘

    CASO 1: Cliente pide opción
    • Vendedor: POST /api/units/{id}/put_on_option/
    • Sistema: Bloquea unidad por 48h
    • Sistema: Programa recordatorio automático
    • Si expira: Libera automáticamente

    CASO 2: Cliente aparta con señas
    • Vendedor: POST /api/units/{id}/separate/
    • Sistema: Marca como separado
    • Sistema: Registra depósito
    • Sistema: Da 15 días para decidir

    CASO 3: Cliente firma contrato
    • Vendedor: POST /api/units/{id}/sign_contract/
    • Sistema: Crea calendario de pagos automático
    • Sistema: Notifica a finance
    • Sistema: Genera documentos

    CASO 4: Cliente hace pago mensual
    • Finance: POST /api/units/{id}/record_payment/
    • Sistema: Actualiza balance
    • Sistema: Calcula próximo pago
    • Si se atrasa: Marca como overdue

    CASO 5: Unidad lista para entrega
    • Construction: Marca como ready_for_delivery
    • Sistema: Notifica a sales
    • Vendedor: POST /api/units/{id}/schedule_delivery/
    • Vendedor: POST /api/units/{id}/deliver/
    • Sistema: Marca como delivered
